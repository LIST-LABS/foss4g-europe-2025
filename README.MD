# Serving and Displaying Vector Tiles with PostgreSQL, Tegola, and OpenLayers: Hands-on Coding Workshop

This document serves as a comprehensive guide for the "Serving and Displaying Vector Tiles with PostgreSQL, Tegola, and OpenLayers: Hands-on Coding Workshop" at FOSS4G Europe 2025. It provides a detailed overview of the workshop's objectives, the technologies employed, necessary prerequisites, and a step-by-step walkthrough of the hands-on exercises.

## Workshop Title & Overview

The workshop, titled "Serving and Displaying Vector Tiles with PostgreSQL, Tegola, and OpenLayers: Hands-on Coding Workshop," offers a practical, end-to-end guide for constructing a robust web mapping application utilizing a suite of open-source tools. Participants will acquire practical skills in managing spatial data within PostgreSQL/PostGIS, generating vector tiles using Tegola, and visualizing these tiles in a React application powered by OpenLayers. The central aim is to deliver a complete, adaptable solution that attendees can readily apply to their own map-driven projects or organizational requirements.

This session is scheduled for FOSS4G Europe 2025, taking place on July 15, 2025, from 14:00 to 18:00 (Europe/Sarajevo) in room PA11. The workshop will be led by Luka Stemberga, Technical Lead at LIST LABS, and Ivan Razum, a Frontend Developer also from LIST LABS.[1] The combined expertise of a technical lead and a frontend developer is particularly beneficial for a full-stack workshop of this nature. This dual perspective ensures that instructions span the entire data pipeline, from the underlying database to the user's browser, providing a holistic understanding of common integration challenges and best practices from both backend and frontend development viewpoints. This structure mirrors how such projects are often collaboratively developed in professional teams.

The selection of PostgreSQL/PostGIS, Tegola, React, and OpenLayers for this workshop is a deliberate choice, reflecting a commitment to leveraging mature, performant, and widely adopted open-source components for a comprehensive geospatial solution. PostgreSQL/PostGIS stands as a widely recognized standard for spatial databases, offering robust data management capabilities. Tegola, implemented in Go, is chosen for its emphasis on high-performance vector tile generation. React and OpenLayers represent leading choices for developing interactive web user interfaces and sophisticated mapping functionalities, respectively. This combination underscores a focus on building scalable, maintainable, and community-supported mapping applications, positioning the workshop as an educational experience in applying leading open-source practices for web GIS development.

## Workshop Goals & What You'll Learn

This hands-on workshop is designed to equip participants with the essential knowledge and practical skills required to construct a complete vector tile pipeline, spanning from spatial data management to a fully functional web map interface. Upon completion of the session, attendees will have developed a working proof-of-concept application and gained the confidence to integrate these techniques into their future projects.

A primary objective is to achieve **Core Workflow Mastery**, enabling participants to understand and implement the entire process of serving and visualizing vector tiles using the integrated stack of PostgreSQL/PostGIS, Tegola, and OpenLayers. This involves practical application of each component's role in the pipeline.

The workshop will delve into **Spatial Data Management**, covering best practices for structuring, indexing, and optimizing geospatial data within PostgreSQL/PostGIS. This foundational step is critical for ensuring high-performance tile generation, particularly when dealing with large datasets, as efficient database design directly impacts the responsiveness of the mapping application.

Participants will then progress to **Vector Tile Generation**, learning how to configure and deploy Tegola to serve vector tiles dynamically. This includes defining map layers and managing geometry transformations, providing the tools necessary to generate tiles on the fly. The ability to generate tiles dynamically from the database ensures that the map always reflects the most current data without requiring a separate, time-consuming tile generation pipeline. This "on-the-fly" capability is invaluable for applications demanding real-time or near real-time data visualization, or for datasets that undergo frequent updates, simplifying the data update workflow considerably compared to static tile sets.

The workshop also focuses on **Interactive Web Mapping**, guiding attendees through the process of building a basic React application that consumes Tegola-served vector tiles. This includes setting up OpenLayers to render these tiles and implementing interactive map features such as popup information on feature clicks and user-driven layer toggling. Within this segment, strategies for maintaining efficient loading times and smooth interactions in a production environment will be discussed, addressing fundamental performance considerations for vector tile consumption. While the subsequent step explicitly covers `ol-mapbox-style` for advanced styling, this step lays the groundwork by demonstrating the inherent power of vector tiles for client-side dynamic styling and interaction. The raw vector data's availability in the browser enables rich user experiences like popups and layer control without requiring additional server requests for styling or feature information, a significant advantage over static raster tiles.

A significant portion of the workshop is dedicated to **Backend-Driven Styling**, a crucial aspect for achieving consistency and maintainability, especially when managing numerous layers. Participants will learn to define Mapbox-style JSON documents and automatically apply these styles in OpenLayers using the `ol-mapbox-style` plugin. This approach centralizes style management, which is particularly beneficial when working with a large number of layers.[1] This architectural pattern decouples styling from the frontend application logic, allowing map designers or GIS specialists to define and update styles without requiring direct frontend developer intervention or application redeployment. This significantly enhances collaboration in larger teams, enables rapid style iteration, and ensures visual consistency across multiple applications or map views consuming the same vector tiles. It effectively transforms styling from a code-centric task into a data-driven configuration.

Finally, the workshop will cover **Performance & Troubleshooting**, offering insights into optimizing vector tile pipelines, effectively handling large datasets, addressing common issues such as geometry errors, and debugging tile generation problems. This proactive approach to common challenges is characteristic of experienced practitioners, providing practical techniques to ensure mapping applications remain stable and efficient even under demanding conditions. The discussion of performance considerations across the entire stack—from optimizing data loading and structuring in PostGIS to efficient tile generation in Tegola and smooth interactions in OpenLayers—underscores that performance is a cumulative effect of optimizations at every layer. This fosters a holistic understanding of performance engineering in geospatial applications, where a bottleneck in one component can impact the entire pipeline.

The workshop's emphasis on "high-performance tile generation," "efficient loading times," "smooth interactions in a production setup," and "centralized style management" for numerous layers extends beyond mere functionality. These elements underscore the critical importance of scalability and maintainability in real-world applications. The workshop is designed not just to demonstrate how to make a system function, but how to make it function effectively and sustainably, preparing participants for production environments where performance and consistent styling across complex projects are paramount.

## Key Technologies Used

This workshop leverages a powerful stack of open-source technologies to construct a modern web mapping application. The selection of these specific tools demonstrates a coherent strategy for building a fully open-source geospatial stack, where each component is a leader in its respective domain, ensuring robustness and community support. This stack provides participants with a viable, cost-effective, and powerful alternative to proprietary GIS solutions, empowering them to build complex mapping applications without licensing constraints.

- **PostgreSQL / PostGIS:** An open-source object-relational database system, augmented by the PostGIS extension. This combination provides robust capabilities for storing, querying, and managing spatial data, serving as the foundational data store for the mapping application.
- **Tegola:** A high-performance, open-source vector tile server implemented in Go. Tegola's core function is to efficiently serve vector tiles from diverse geospatial data sources, with strong integration for PostGIS.[1] It acts as the robust engine responsible for transforming raw spatial data from PostgreSQL/PostGIS tables into a streamlined, tiled format consumable by map clients.[1]
- **React:** A widely adopted JavaScript library for building user interfaces. React facilitates a component-based approach to development, enabling the creation of interactive and dynamic web applications.
- **OpenLayers:** A powerful, open-source JavaScript library specifically designed for building interactive web mapping applications directly within the browser.[1] OpenLayers offers a comprehensive API for handling diverse geospatial data, capable of displaying maps and layers from virtually any source, including standard tiles, WMS, GeoJSON, KML, and, critically for this workshop, vector tiles.[1]
- **ol-mapbox-style:** A utility library that bridges the gap between OpenLayers and Mapbox GL Style specifications.[1] Its primary function is to enable OpenLayers to render vector tiles using styles defined in the Mapbox Style Specification (JSON).[1] This capability simplifies styling workflows, allowing for the reuse of complex, dynamic Mapbox GL styles directly within an OpenLayers application and ensuring consistent map aesthetics across various platforms or projects.[1] The emphasis on `ol-mapbox-style` for centralizing style management is a critical architectural decision. Without it, styling vector tiles in OpenLayers would typically involve writing complex JavaScript styling functions, which can become unmanageable with numerous layers or frequent style changes. Mapbox Style JSON provides a declarative, standardized method for defining styles, promoting a clear separation of concerns (data/tiles on the backend, style definition on the backend, rendering on the frontend). This significantly improves collaboration in larger teams, enables rapid style iteration, and ensures visual consistency across multiple applications or map views consuming the same vector tiles. It effectively transforms styling from a code-centric task into a data-driven configuration. Furthermore, by adopting the Mapbox Style Specification (JSON), the workshop leverages a widely accepted industry standard for vector tile styling, fostering interoperability and future-proofing skills that are transferable to other mapping platforms and tools adhering to this specification.

## Hands-on Workshop Guide

This section provides a detailed outline of the step-by-step coding exercises that will be performed during the workshop. Participants will find sample datasets and code snippets within the cloned repository, typically organized in `data/`, `backend/`, and `frontend/` directories, to facilitate the learning process.

### Step 1: Data Preparation & PostgreSQL/PostGIS Setup

This foundational step initiates the workshop by focusing on best practices for storing and indexing geospatial data within PostgreSQL, enhanced by the PostGIS extension.

The concepts covered include data modeling for spatial data, which involves designing database schemas that efficiently store geographic features. Strategies for creating efficient spatial indexes, such as GiST indexes, will be explored, as these are crucial for accelerating spatial queries. Furthermore, query optimizations for high-performance tile generation will be discussed, emphasizing how well-crafted SQL queries are essential for Tegola's ability to dynamically create vector tiles. Participants will also gain an understanding of how various PostGIS functionalities contribute to preparing data for optimal vector tiling. The emphasis on "high-performance tile generation" and "maintaining performance when dynamically creating vector tiles, even for large datasets" underscores a critical aspect of geospatial development: data design directly influences application performance. Poorly indexed or structured data will inevitably lead to slow tile generation and a sluggish map experience. This step teaches participants that the foundation of a high-performing web map lies not just in frontend rendering, but in how the data is managed at its source, instilling a "performance-first" mindset from the database layer upwards.

For the sake of simplicity and to ensure a consistent environment across all participants' machines, the database will be deployed using Docker.[1] This approach effectively bypasses the common complexities and dependencies associated with local software installations, such as operating system specific configurations or dependency conflicts, which often consume valuable workshop time. Docker ensures a standardized and reproducible environment, allowing participants to immediately engage with the core content of the workshop without spending hours debugging local setups. This directly contributes to a more productive and less frustrating learning experience. Participants will be guided through using Docker images specifically designed for PostGIS, with options including `https://github.com/postgis/docker-postgis` and `https://hub.docker.com/r/kartoza/postgis/`.[1] Detailed Docker commands for pulling, running, and initializing the PostGIS container will be provided within the workshop materials, likely in a dedicated `backend/` or `docker/` folder within the repository. Instructions will also cover how to load the previously downloaded `.osm.pbf` data into the PostGIS database, which will involve setting up appropriate tables and spatial indexes using tools like `osm2pgsql`.

### Step 2: Tegola Vector Tile Server Setup

Following the data preparation, this step guides attendees through the process of installing and configuring Tegola to efficiently serve vector tiles directly from the prepared PostgreSQL data.

The concepts covered include the installation and fundamental configuration of Tegola. Participants will learn how to create a `config.toml` file, which is central to Tegola's operation, enabling the definition of map layers and their linkage to specific PostgreSQL tables. The workshop will also address how to handle geometry transformations and projections within Tegola's configuration, ensuring data is served correctly for mapping applications. Furthermore, techniques for managing multiple layers and styles using Tegola's straightforward configuration syntax will be demonstrated. This step clarifies Tegola's pivotal role as the "robust engine" responsible for transforming raw spatial data into a streamlined, tiled format readily consumable by map clients.[1]

To further streamline the workshop's progress and maintain environmental consistency, Tegola will also be served through Docker.[1] The recommended Docker image for Tegola is `https://hub.docker.com/r/gospatial/tegola`.[1] Detailed Docker commands for running the Tegola server, alongside a sample `config.toml` file that maps PostGIS tables to Tegola layers, will be provided within the workshop repository. These instructions will include explanations of how to define data sources, layers, and specific SQL queries within the `config.toml` to expose various geographic features, such as roads, buildings, or water bodies, as distinct vector tile layers.

A critical aspect of the workshop's design is its provision for troubleshooting and fallback mechanisms. Should participants encounter any difficulties in getting Tegola to run locally on their machines, a publicly published Tegola service is available to ensure continuous participation. This service can be accessed at `https://foss4g-2025.listlabs.net/capabilities`.[1] Additionally, a complete Docker container setup for the entire workshop environment is available at `https://git.li-st.net/pubiic/foss4g-workshop`.[1] Providing these accessible fallbacks demonstrates exceptional foresight and a strong commitment to participant success. It acknowledges that local environment issues are common in hands-on workshops and offers immediate, viable solutions. This ensures that no participant is left behind due to technical difficulties with the backend setup, allowing everyone to proceed to the crucial frontend integration and styling steps, which are central to the workshop's learning objectives.

### Step 3: Frontend Application Integration

This section of the workshop shifts focus to the client-side, guiding participants through building a basic React application designed to consume and display the vector tiles served by Tegola, utilizing the OpenLayers mapping library.

The concepts covered include setting up a fundamental React application structure, which forms the basis for the web map. Participants will learn how to configure OpenLayers to effectively fetch and render vector tile sources directly from their running Tegola server. A significant portion of this step involves implementing interactive map features, such as displaying popup information when a user clicks on a map feature, and enabling user-driven layer toggling, allowing users to display or hide different map layers as needed. Strategies for maintaining efficient loading times and ensuring smooth interactions in a production setup will also be discussed, encompassing basic performance considerations specific to vector tile consumption. While the subsequent step explicitly covers `ol-mapbox-style` for advanced styling, this step lays the groundwork by demonstrating the inherent power of vector tiles for client-side dynamic styling and interaction. The raw vector data's availability in the browser enables rich user experiences like popups and layer control without requiring additional server requests for styling or feature information, a significant advantage over static raster tiles.

Participants will follow along with the coding exercises in their preferred integrated development environment (IDE), such as Visual Studio Code.[1] Detailed code snippets and comprehensive explanations will be provided within the `frontend/` directory of the workshop repository. These materials will guide attendees through initiating a new React project, installing OpenLayers, creating a core `MapComponent.js` to initialize the OpenLayers map, and crucially, adding a `VectorTileSource` that points to the local Tegola server (e.g., `http://localhost:8080/v1/{z}/{x}/{y}.pbf`). Further instructions will cover implementing event listeners for map interactions, such as `map.on('click',...)`, to display feature properties in a popup, and integrating user interface controls, like checkboxes, to manage the visibility of different vector tile layers. The discussion on "strategies for maintaining efficient loading times and smooth interactions in a production setup" within this frontend integration step underscores that performance is not an afterthought but an integral part of the application's design, even for a basic proof-of-concept. This teaches participants that frontend optimization for mapping applications extends beyond mere rendering; it encompasses intelligent data loading, effective management of map state, and ensuring a responsive user interface, particularly when dealing with potentially large volumes of vector tile data.

### Step 4: Backend-Driven Styling with `ol-mapbox-style`

This section represents a key focus of the workshop, demonstrating an advanced approach to map styling by centralizing style logic on the backend. This method is crucial for achieving consistency and maintainability, especially in projects with numerous or frequently changing layers.

The concepts covered include a thorough understanding of the Mapbox Style Specification (JSON), which serves as a declarative language for defining map styles.[1] Participants will learn how to define a Mapbox-style JSON document that precisely describes the visual appearance of vector tile layers, including attributes such as colors, line weights, and visibility rules. The workshop will then demonstrate how to store this style document in a centralized location, which could involve serving it directly from the backend or as a static file. A core component of this step is leveraging the `ol-mapbox-style` plugin in OpenLayers to automatically apply these backend-defined styles to the vector tile layers. This approach offers significant benefits: it simplifies collaboration among team members (e.g., between map designers and developers), ensures consistent styling across different projects or teams, and eliminates the need for repetitive frontend adjustments whenever data or styles change.

The core theme of "moving layer styling logic to the backend" is a powerful architectural pattern that effectively decouples styling from the frontend application logic.[1] This means that map designers or GIS specialists can define and update styles without requiring direct intervention from frontend developers or necessitating a new application deployment. This significantly enhances collaboration in larger teams, allows for rapid iteration on styles, and ensures visual consistency across multiple applications or map views that consume the same vector tiles. It transforms styling from a code-centric task into a more data-driven configuration. Furthermore, by adopting the Mapbox Style Specification (JSON), the workshop embraces a widely accepted industry standard for vector tile styling. This standard is supported by various tools and libraries beyond Mapbox's own ecosystem, including MapLibre and OpenLayers via `ol-mapbox-style`. This choice promotes interoperability and future-proofing, as participants acquire a skill set transferable to other mapping platforms and tools that adhere to the Mapbox style specification, thereby broadening their overall capabilities.

Practical implementation will involve detailed code examples demonstrating how to create a `style.json` file and integrate it seamlessly with OpenLayers using `ol-mapbox-style`. This will include creating a `style.json` file that defines layers, sources, and various paint and layout properties for the vector tiles. Participants will learn to install the `ol-mapbox-style` library and use its `apply` function to load the JSON style into their OpenLayers map, for instance, `olms.apply(map, 'path/to/your/style.json');`. The workshop will also include a discussion on how the backend could dynamically serve different `style.json` files based on specific user roles or varying application contexts, further enhancing the flexibility of this styling approach.

### Step 5: Performance Considerations & Troubleshooting

This concluding hands-on step addresses real-world challenges, common pitfalls, and practical strategies for ensuring the stability and efficiency of mapping applications built with vector tiles. The inclusion of a dedicated "Performance and Troubleshooting" section demonstrates a mature approach to software development, acknowledging that real-world applications inevitably encounter issues and that developers require practical strategies to diagnose and resolve them. This step moves beyond theoretical implementation to practical application, preparing participants for the realities of deploying and maintaining mapping solutions and fostering a mindset of building resilient systems.

The concepts covered encompass comprehensive **Performance Tuning** across the entire vector tile pipeline. This includes optimizing tile generation at both the Tegola and PostgreSQL/PostGIS levels, focusing on techniques such as crafting efficient SQL queries and implementing appropriate indexing strategies. Client-side rendering performance will also be addressed, with discussions on simplifying geometries for lower zoom levels and effectively managing feature density to ensure smooth map interactions. While not deeply covered, the importance of caching strategies for optimizing data loading will be highlighted to provide a smoother user experience. The discussion of performance considerations across the entire stack—from "optimizing data loading and proper data structuring" in PostGIS to "optimizing tile generation" in Tegola and ensuring "efficient loading times and smooth interactions" in OpenLayers—underscores that performance is not isolated to a single component but is a cumulative effect of optimizations at every layer. This fosters a holistic view of performance engineering in geospatial applications, where a bottleneck in the database can impact the frontend, and vice-versa, encouraging participants to consider the entire pipeline when designing and optimizing their solutions.

Furthermore, the workshop will delve into **Troubleshooting Common Issues** that frequently arise in vector tile pipelines. This includes strategies for effectively handling large datasets, which often pose significant performance challenges. Participants will learn how to address geometry errors, such as invalid geometries in PostGIS, which can lead to failures in tile generation. Practical techniques for debugging tile generation issues will be explored, utilizing tools like Tegola logs, network requests analysis, and direct inspection of vector tile content. The session will also cover general debugging techniques applicable across the full vector tile pipeline, equipping attendees with practical skills to self-diagnose and fix problems, thereby reducing reliance on external support.
